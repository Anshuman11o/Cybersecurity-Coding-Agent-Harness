# Language-wide agent classes in Stage 0.5 agent mode

Standing constraint: never search for, read, or reference any answer-key or ground-truth material anywhere on this machine. Work only in the harness checkout. No paid scans and no model API calls; every test uses synthetic fixtures.

## Problem

In agent mode (the playbook agent wrote `class-selection.json`), `stage05-lane-selector-perfile` drops the floor and routes selected classes to a file only through signals: `signal-classes.json` plus each overlay entry's `signals`. Classes the agent *adds* are routed the same way, although most of them are language-scoped (their overlay `framework` names a language or platform). In a C product run the agent added two classes with framework `c` and signals `[deserialize]` and one with framework `c` and signals `[file_io]`; 85 of 250 C files fired no signal and were skipped with "No selected class applies to this file". Runs with a Solidity-scoped added class and three Android-scoped added classes showed the same partial reach (140/143 and 34, 11 and 9 of 34 lanes).

## Approved change (owner-approved)

1. **Language-wide agent classes.** Every agent-added class (selected, present in the overlay) whose `framework` maps to a file language goes on every hunt lane in that language, in addition to its signal routing. The mapping is one exported table in `shared/lane-languages.ts`: `frameworkLanguages(framework)`. A framework equal to a language id produced by `EXTENSION_LANGUAGES` (stage0-recon) maps to itself; `FRAMEWORK_LANGUAGE_ALIASES` adds `android` -> kotlin, java; `c/c++` and `c++` -> c, cpp; `evm` and `ethereum` -> solidity. Any other framework keeps signal-only routing. Recorded as `class_basis['language-wide']`.
2. **Base-class fallback.** A hunt-eligible lane that would otherwise end with zero classes hunts with its language's base classes (the classes from rule 1) instead of being skipped; recorded as `class_basis['language-base']`. A language with no added class behaves as before (skip with the no-selected-class reason).
3. The strict invariant stays: the union of hunt-lane classes equals the agent selection. Language-wide classes are applied before the unrouted rule, so an added class whose language has no hunt lane is still unrouted and goes on every hunt lane.
4. Without an agent selection (benchmark / fixed-class mode) the manifest is byte-for-byte unchanged, including when an overlay exists. v1 (`stage05-lane-selector`) untouched.
5. One log line: N lanes received language-wide classes, M lanes rescued from skip by base classes (lanes with no signal-routed class and no unrouted class).

## Verification

- `stage05-lane-selector-perfile/src/language-wide.test.ts`: C fixture (signal-less `.c`/`.h` lanes hunt with the class, a `.c` lane with the signal gets it too, a signal-less `.py` lane is still skipped and a `.py` lane gets it only through its own signal); `android` reaches `.kt` and `.java`, not `.py`; unknown framework (`django`) unchanged; language-wide class with no lane of its language still unrouted; no selection, with and without an overlay, byte-identical to goldens generated by the pre-change selector.
- Every scanner suite and `tsc --noEmit` for the selector package.
