CONTEXT / WHY: tools/scanner/stage0-recon/src/recon.ts currently hardcodes exact absolute paths:
  TARGET_DIR = target-apps/juice-shop-blind  (not parameterized at all -- nothing else can ever be scanned)
  SERVER_TS  = TARGET_DIR/server.ts           (the ONLY backend file ever AST-parsed for the route table)

There is no directory walk anywhere in Stage 0 -- it reads exactly these 4 named files/paths and nothing else. We confirmed this causes real, silent coverage gaps: frontend/src/app/app.routing.ts (Angular router config -- 3 real vulnerabilities live there) and the Solidity smart-contract files under data/static/web3-snippets/*.sol (2 real vulnerabilities live there) never get discovered as scannable surface at all -- they don't appear in ANY lane's seed_files downstream, because Stage 0 never told anyone they exist. This isn't a "Stage 2 lane missed it" problem, it's a "Stage 0 structurally can't see it" problem.

This scanner is meant to eventually run against arbitrary production codebases in arbitrary languages/frameworks (Next.js, NestJS, Fastify, non-Node stacks), not just this one Express+Angular Juice Shop copy. Right now it would silently fail (or crash) against anything else, because everything is hardcoded to this exact repo's file layout.
